# ASI2-17 — Inscripcion solo en clase activa

La accion autentica al alumno por si misma, valida UUID antes del cast y usa una sola
sentencia INSERT SELECT desde una clase activa. FOR SHARE impide que una desactivacion
concurrente modifique la fila entre elegirla e insertar. Si la desactivacion gana primero,
la seleccion reevalua el predicado y no inscribe. No usa transacciones interactivas.

Clase inexistente/inactiva retorna error controlado; duplicado de clase activa es
idempotente. La UI revierte la seleccion optimista y muestra el error. AlumnoId viene
de sesion. Inscripciones previas no se borran al desactivar; siguen con la politica vigente.

La accion administrativa y completarPerfil tienen rutas de inscripcion independientes;
se revisaron por lectura pero no se cambiaron, para no tocar las tareas de autorizacion
en paralelo. No se define una excepcion admin por este cambio: acordar su politica antes
de aplicar el mismo guardado alli. Esta tarjeta cubre inscribirse desde /clases.

Sin migracion. Pruebas puras de UUID/parametrizacion y construccion SQL, mas suite existente
y TypeScript. Pendiente: comportamiento real PostgreSQL en clase activa/inactiva/inexistente,
dos altas concurrentes y desactivacion concurrente, por Julio en entorno aislado o ensayo
autorizado; no ejecutar probar:base. Validacion de UI en proximo despliegue agrupado.
